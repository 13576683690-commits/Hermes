# 风险门禁

> 所有模块必须先判断风险。不确定时按最高级处理。

## 风险等级

| 等级 | 定义 | 处理 |
|---|---|---|
| 低 | 只读、本地草稿（src/ 修改）、可回滚 | 直接处理，完成后回传 |
| 中 | 追加 data.json、远端推送、构建部署 | 暂停，主控判断后执行 |
| 高 | 修改/删除历史数据、force push、仓库设置变更 | 主控提交用户确认后才能继续 |
| 不确定 | 无法判断影响范围或回滚方式 | 按高风险处理 |

## 项目特有风险

| 风险项 | 等级 | 触发条件 | 处理方式 |
|---|---|---|---|
| data.json 历史数据篡改 | 高 | 修改任何已存在的条目 | 禁止操作；如必须修改，用户确认 |
| 构建失败部署 | 中 | npm run build 返回非零 | 阻断推送，修复后重新构建 |
| 敏感信息泄露 | 高 | 推送包含密钥/token/个人信息 | 推送前扫描，发现即阻断 |
| Web 资源中文命名 | 中 | 文件名/路径含中文字符 | 重命名为英文/拼音，避免 CI/CD 404 |
| node_modules 误删 | 低 | git clean 或分支操作误删 | 重新 npm install |
| SSH key 失效 | 中 | git push 认证失败 | fallback 到 Keychain PAT |

```
影响范围：
为什么有风险：
是否含敏感信息：是 / 否
回滚方式：
建议动作：
需要主控判断：是 / 否
需要用户确认：是 / 否
```

## 敏感信息检查清单

写入文件、提交 Git、推送远端前必须检查：

- [ ] 无 API key / token / secret
- [ ] 无账号密码
- [ ] 无个人信息（姓名、手机号、地址等）
- [ ] 无未脱敏数据
- [ ] .gitignore 正确排除 node_modules/ dist/ .env
